# SETU-Culture single-source extraction and generation

`setu_benchmark_pipeline.py` consumes one manually downloaded PDF at a time. It no longer resolves or compares two URLs. The source itself may discuss relationships between two or more cultures, and the LLM extracts the relationship before generating benchmark questions from the local document text.

## Workflow

1. Read a ten-source batch created from `cultural_crawl_4000/Division/Suruchi_english_only_sources.csv`.
2. Join each batch item to `cultural_crawl_4000/local_archive/source_manifest.csv` by `record_id`.
3. Read the PDF at `local_document_path` and extract page-marked text locally with `pypdf` or `PyPDF2`.
4. Prompt 1 extracts source language, relationship label, periods, shared-element category, evidence summary, uncertainty, and confidence from the local text.
5. Prompt 2 extracts Culture A/B country, region, macro-region and generates exactly three distinct scenario/question packages from the same evidence.
6. Write three output rows per successfully processed source in one JSON and one CSV benchmark export per batch.

No source pairs are generated by this pipeline.

## Requirements

```bash
python3 -m pip install openai
python3 -m pip install pypdf
```

Configure the OpenAI-compatible AgentRouter endpoint:

```bash
export LLM_API_KEY="your-agentrouter-key"
export LLM_BASE_URL="https://agentrouter.org/v1"
export LLM_MODEL="gpt-5.6-sol"
export SETU_AUTHOR="Validator name"
export LLM_USER_AGENT="Kilo-Code/5.3.0"
export LLM_STAINLESS_LANG="python"
```

## Create ten-source batches

The current Suruchi English-only CSV contains 882 rows and 882 unique `record_id` values.

Batch preparation creates 89 batches: 88 batches of 10 and one final batch of 2. Each batch is written as a matching CSV and JSON file under `cultural_crawl_4000/batches_10`.

```bash
python3 setu_benchmark_pipeline.py \
  --source-file cultural_crawl_4000/Division/Suruchi_english_only_sources.csv \
  --batch-dir cultural_crawl_4000/batches_10 \
  --prepare-batches \
  --batch-size 10
```

Each batch directory contains:

```text
batch_0001.json
batch_0001.csv
batch_0002.json
batch_0002.csv
...
```

The batch item uses the crawler's `record_id` as both `Instance_ID` and `source_record_id`. No legacy template file is used.

Source uniqueness is defined as `source_id + URL`; when URL is empty, the crawler's external ID or `record_id` is used. Repeated query matches remain available in `matched_queries_json` rather than creating duplicate source rows.

## Run one batch

```bash
python3 setu_benchmark_pipeline.py \
  --batch-file cultural_crawl_4000/batches_10/batch_0001.json \
  --out-dir setu_culture_generated/batch_0001 \
  --stage all
```

The batch writes:

```text
setu_culture_generated/batch_0001/setu_culture_questions.json
setu_culture_generated/batch_0001/setu_culture_questions.csv
setu_culture_generated/batch_0001/01_extractions.jsonl
setu_culture_generated/batch_0001/02_generations.jsonl
setu_culture_generated/batch_0001/errors.log       # only if failures occur
```

Rerunning the same command skips completed `Instance_ID` values in the intermediate JSONL files.

`Culture_Source` in the final JSON/CSV is populated from the manifest's `resolved_url`. The regenerated manifest intentionally leaves `resolved_url` blank until it is filled manually; processing a record before that field is completed will therefore produce an empty `Culture_Source`. The original URL remains available in the batch/source metadata. Each source has `Question_Number` values `1`, `2`, and `3` to distinguish its three generated packages; `Instance_ID` remains the source ID for all three rows.

## Test without API calls

```bash
python3 setu_benchmark_pipeline.py \
  --batch-file cultural_crawl_4000/batches_10/batch_0001.json \
  --out-dir /tmp/setu_batch_dry_run \
  --stage extract \
  --dry-run
```

Dry-run mode still requires a readable local PDF. It prepares Prompt 1 records with local document text but does not call the LLM or create generation output.

## Prompt responsibilities

Prompt 1 uses only one source record and the configured relationship taxonomy. It must be conservative: similarity alone supports parallel, uncertain, or false-friend labels, not transmission.

Prompt 2 uses the source text and extraction to identify Culture A/B and generate exactly three distinct question packages. If the source does not establish a country, region, macro-region, or chronology, it must return `unknown` or `uncertain` rather than guess. A generation response with fewer or more than three packages is rejected for final export.

## Local-document requirements

Every processed batch record must have a matching manifest row with:

```text
local_document_path -> existing .pdf file
file_extension      -> .pdf
resolved_url        -> final public source link
```

The regenerated manifest starts with `resolved_url` and `local_document_path` blank for all 882 records. Complete those fields manually before processing the corresponding batch record.

Records without a local PDF are skipped and written to `errors.log`; the pipeline does not fall back to metadata-only prompting. PDF text is page-marked as `[Page N]` and bounded by `--max-text-chars` (default 120,000).

## Notes and suggestions

- `configured_relationship_type` and `configured_shared_element` from the crawler are provenance hints, not gold labels. Prompt 1 must independently assess the source.
- Many Crossref records contain metadata but no abstract. Those records may yield low-confidence or uncertain extractions and should be reviewed before benchmark inclusion.
- Process a pilot batch first, inspect quality, then scale across all batches.
- Keep each batch output directory separate so failures and revisions are auditable.
